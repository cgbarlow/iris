## ADR (WH(Y) Statement format)

**In the context of** Iris having a complete DoView notation (ADR-094) with four element types (`outcome_box`, `final_outcome`, `overview_tile`, `source_reference`), one relationship type (`causal_link`), and two diagram types (`outcomes_map`, `overview`), and a mature SparxEA import pipeline for .qea/.eap files, where DoView models are commonly authored in PowerPoint (.pptx) format using tools like the AI DoView Drawing Prompt (DoViewPlanning.org),

**facing** the challenge that there is no way to import existing DoView PPTX models into Iris, requiring users to manually recreate multi-page DoView models (10-20 slides with overview navigation, final outcomes, and outcomes maps) that already exist in a well-structured PowerPoint format with consistent shape patterns (colored rectangles for outcome boxes, rightArrow shapes for causal links, hyperlinks for inter-slide navigation),

**we decided for** implementing a DoView PPTX import module (`backend/app/import_pptx/`) using the `python-pptx` library, with structural compliance validation to ensure only valid DoView models are imported, heuristic shape classification (by fill color, geometry, hyperlink presence, and position), column-based causal link inference from arrow shapes, and cross-diagram navigation linking via hyperlink resolution — following the established import_sparx pipeline pattern,

**and neglected** raw XML parsing without python-pptx (fragile, reimplements OOXML parsing), a generic PPTX import supporting arbitrary presentations (scope creep, no reliable shape classification without DoView structural assumptions), and manual user-guided import with shape-by-shape confirmation (too slow for 10-20 slide models with hundreds of shapes),

**to achieve** one-click import of existing DoView PPTX models into Iris with correct element typing, visual fidelity (preserved colors), causal link structure, and inter-diagram navigation, enabling immediate editing and collaboration within Iris,

**accepting that** the heuristic classification depends on consistent DoView PPTX structure (as generated by the AI DoView Drawing Prompt), may not handle heavily customized PowerPoint files, and column-to-column causal links create all-to-all connections between adjacent columns (matching DoView methodology but potentially producing many edges).

---

## Problem Statement

Users who have existing DoView models authored in PowerPoint (a common authoring format for DoView, especially when using the AI DoView Drawing Prompt from DoViewPlanning.org) cannot bring those models into Iris. These PPTX files follow a consistent structural pattern: an overview slide with navigation tiles, a final outcomes slide, and multiple outcomes map slides with columnar causal flows. Manually recreating a 10-20 slide DoView model with hundreds of shapes, causal links, and inter-slide navigation is impractical. Iris needs a purpose-built PPTX import pipeline that understands DoView structure and can reliably classify shapes into the correct DoView element types.

## Decision Details

### 1. DoView Compliance Validation

Before importing, the PPTX file is validated against four hard-fail criteria to ensure it is a genuine DoView model rather than an arbitrary presentation:

1. **Slide count** — the file must contain at least 3 slides (minimum: overview + final outcomes + one outcomes map).
2. **Overview slide** — slide 1 must contain shapes with internal hyperlinks pointing to other slides (navigation tiles).
3. **Final outcomes slide** — slide 2 must contain white/light-grey filled rectangles arranged vertically (final outcome boxes).
4. **Outcomes map slides** — at least one slide (3+) must contain colored rectangles arranged in a columnar left-to-right layout with arrow shapes between columns.

Files that fail any hard-fail criterion are rejected with a descriptive error. Three additional warning-level checks (title shape presence, consistent color palette, arrow shape count) generate import warnings but do not block import.

### 2. Shape Classification Heuristics

Shapes are classified into DoView element types using a combination of signals:

| Signal | Used For |
|--------|----------|
| **Fill color** | Distinguish `outcome_box` (pastel yellow/colored) from `final_outcome` (white/near-white) |
| **Shape geometry** | `rightArrow` / `chevron` auto-shapes identify causal link arrows; rectangles identify element boxes |
| **Hyperlink presence** | Shapes with internal slide hyperlinks on the overview slide become `overview_tile` nodes |
| **Slide position** | Slide 1 = overview context, slide 2 = final outcomes context, slides 3+ = outcomes map context |
| **Vertical position** | Shapes in the footer region of any slide are classified as `source_reference` if they match source patterns |

### 3. Four-Pass Import Pipeline

The import follows a four-pass architecture (mirroring the established import_sparx pattern):

1. **Pass 1 — Validate:** Run DoView compliance validation on the uploaded PPTX file. Reject non-compliant files immediately.
2. **Pass 2 — Parse & Classify:** Extract all shapes from all slides using `python-pptx`. Classify each shape into a DoView element type using the heuristic rules. Record shape positions (EMU coordinates), fill colors, text content, and hyperlinks.
3. **Pass 3 — Create Entities & Diagrams:** Create one diagram per slide (overview or outcomes_map type). Create entities for each classified shape. Convert EMU coordinates to pixel positions (96 DPI). Infer `causal_link` relationships between adjacent columns based on arrow shapes. Preserve fill colors as visual overrides.
4. **Pass 4 — Resolve Cross-Links:** Resolve internal hyperlinks from overview tiles to their target diagrams. Set `linkedDiagramId` on overview_tile nodes. Wire up inter-diagram navigation.

### 4. python-pptx Dependency

The import module uses `python-pptx` (BSD-licensed) as the sole PPTX parsing library. This is a mature, well-maintained library that handles OOXML complexity (slide layouts, shape trees, color inheritance, hyperlink relationships) without requiring raw XML manipulation. It is added as an optional dependency (`pip install iris[pptx]`) to avoid increasing the base install size for users who do not need PPTX import.

## Consequences

**Positive:**
- One-click import of existing DoView PPTX models into Iris with correct element typing and visual fidelity
- Follows the established import_sparx pipeline pattern, maintaining architectural consistency
- Compliance validation prevents garbage-in from arbitrary PowerPoint files
- Heuristic classification leverages the structural consistency of DoView PPTX files for reliable results
- Optional dependency keeps the base install lean

**Negative / Risks:**
- Heuristic classification may misclassify shapes in heavily customized or non-standard DoView PPTX files
- Column-to-column causal link inference creates all-to-all connections between adjacent columns, which may produce more edges than intended for some models
- python-pptx is an additional dependency that must be kept up to date
- The import pipeline is specific to DoView PPTX structure and cannot be reused for other PowerPoint import scenarios without significant adaptation
