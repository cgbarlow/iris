# SPEC-135-A: DocRef Supabase migration

ADR: [ADR-135](../ADR-135-DocRef-Supabase-Migration-Parity.md)

## Surface

One new file:

```
backend/app/migrations/supabase/m043_docref_tables.sql
```

Postgres equivalent of the SQLite Python migration
`backend/app/migrations/m034_docref_tables.py`. Applied automatically
by `backend/app/migrations/supabase/runner.py` (lex order across
`m*.sql`).

## Schema

### `docref_documents`

| Column | Type | Notes |
|---|---|---|
| `id` | `TEXT PRIMARY KEY` | UUID generated by service. |
| `slug` | `TEXT NOT NULL` | URL slug from legislation.docref.nz. |
| `title` | `TEXT NOT NULL` | Human-readable document title. |
| `latest_version` | `TEXT NOT NULL` | ISO date `YYYY-MM-DD`. |
| `source_url` | `TEXT NOT NULL` | docref.nz HTML source URL. |
| `csv_url` | `TEXT NOT NULL` | docref.nz chunked CSV URL. |
| `chunk_count` | `INTEGER NOT NULL DEFAULT 0` | Number of imported chunks. |
| `status` | `TEXT NOT NULL DEFAULT 'available'` | `available` / `importing` / `imported` / `error`. |
| `error_message` | `TEXT` | Last import error. |
| `imported_at` | `TIMESTAMPTZ` | Set on successful import. |
| `imported_by` | `TEXT` | User id of importer. |
| `created_at` | `TIMESTAMPTZ NOT NULL` | Row creation timestamp. |
| `updated_at` | `TIMESTAMPTZ NOT NULL` | Last update timestamp. |

Constraints:

- `UNIQUE (slug, latest_version)` — same document version can appear
  only once.

Indexes:

- `idx_docref_documents_slug ON docref_documents (slug)`
- `idx_docref_documents_status ON docref_documents (status)`

### `docref_chunks`

| Column | Type | Notes |
|---|---|---|
| `id` | `TEXT PRIMARY KEY` | UUID per chunk. |
| `document_id` | `TEXT NOT NULL REFERENCES docref_documents(id) ON DELETE CASCADE` | Parent document. |
| `chunk_id` | `TEXT NOT NULL` | Source CSV chunk identifier. |
| `url` | `TEXT NOT NULL` | docref.nz fragment URL. |
| `content` | `TEXT NOT NULL` | Chunk text content. |
| `sort_order` | `INTEGER NOT NULL DEFAULT 0` | Position within document. |

Constraints:

- `UNIQUE (document_id, chunk_id)` — chunk_id is unique per document.

Indexes:

- `idx_docref_chunks_document_id ON docref_chunks (document_id)`

## Type translation

The service layer (`backend/app/docref/service.py`) writes timestamps
as ISO strings via `datetime.isoformat()`. The `SupabaseAdapter`
(`backend/app/db/adapter.py:_convert_params`) coerces those strings to
`datetime` for asyncpg, and `_normalize_row` converts `datetime` back
to ISO strings on read so the Pydantic models in
`backend/app/docref/models.py` (which declare `str | None`) work
unchanged.

Concretely: SQLite stores TEXT, Postgres stores TIMESTAMPTZ, the
service code reads `str` from both via the adapter — no service-layer
changes required.

## Row Level Security

Both tables enable RLS. Two policies per table:

- `*_select` — `USING (TRUE)` — readable by every authenticated user
  (the Legislation picker is a UI affordance every role uses).
- `*_admin` — `USING (EXISTS … profiles WHERE id = auth.uid() AND
  role = 'admin')` — only admins can write (refresh / import / delete
  chunks).

Policy creation is wrapped in `DO $$ … pg_policies … $$` blocks so
re-running the migration is idempotent (mirrors the m034_extensions
pattern).

## Verification

`backend/tests/test_migrations/test_docref_schema.py` is a static
parser that runs in standard CI (no Postgres needed). It asserts:

1. `m043_docref_tables.sql` exists.
2. Both tables have a CREATE statement.
3. Every column the service layer reads/writes is declared.
4. The cascade FK from `docref_chunks.document_id` to
   `docref_documents.id` is preserved.
5. Both unique constraints are present.
6. All three indexes are created.
7. RLS is enabled on both tables.

End-to-end verification on a Supabase deployment:

1. Apply `m043_docref_tables.sql` via psql or the Supabase SQL Editor.
2. Reload the Iris AI page in the browser.
3. Open the Legislation dropdown — it should show "(no documents)" or
   the document list, no longer the "Failed to load documents" error.
4. Install the DocRef extension as admin (Settings → Extensions →
   DocRef → Install). The post-install index refresh populates
   `docref_documents`.
5. Click any document → Import → confirm `chunk_count > 0` and the
   document is then usable as Ask context.

## Migration ordering

The Supabase runner applies files in lex order. `m043` slots between
`m042_personal_access_tokens.sql` and any future migrations. No
existing migration depends on the DocRef tables, so the relative
ordering is academic — placement is purely "next free number".

## Backfill

There is no backfill. The DocRef extension is opt-in; clean
deployments have no rows. UAT environments that have been failing on
"Failed to load documents" gain access the moment the migration is
applied — no data loss to recover from.

## Out of scope

- Live Postgres integration tests against a Supabase test container.
  Belongs in a separate deployment-test workstream rather than this
  fix.
- Backfill from any prior misconfiguration. There was no prior schema
  to backfill from.

## Amendment 2026-05-05 — fire-and-forget import (issue #27)

### Surface change

- `backend/app/docref/router.py::import_document` returns **HTTP 202**
  immediately. The async work is launched via `asyncio.create_task`
  inside the route handler.
- `backend/app/docref/service.py` adds `start_import_document(db, id)`
  which marks status `importing` and commits, and returns a result
  matching `DocRefImportResponse` with `chunk_count=0`. The original
  `import_document(...)` is preserved unchanged for the background
  task and existing tests.
- `frontend/src/lib/components/DocRefSelector.svelte`:
  - Optimistically flips the clicked document to `importing` so the
    spinner shows the moment the click handler fires.
  - After the POST returns, polls `/api/docref/documents` every 3 s
    while any row has `status === 'importing'`; clears the timer on
    component teardown.
  - Removes the now-unreachable "Import failed" error path that
    previously fired on edge-timeout 502s — the request can no
    longer time out because the heavy lifting runs off-thread.

### Why a background task and not BackgroundTasks (FastAPI)

`fastapi.BackgroundTasks` runs **after** the response is sent but
before the worker frees up — it would still hold the request worker
for the duration of the import. `asyncio.create_task` from inside the
handler hands the work to the event loop and returns the response
straight away, freeing the worker. This matches the existing pattern
for the post-install DocRef index refresh in
`extensions/router.py`.

### Why poll instead of SSE/WebSockets

DocRef imports are infrequent (admins, occasional). Polling every 3 s
while a single dropdown is open costs nothing meaningful and avoids a
new transport channel. SSE/WebSockets become attractive if/when we
have many concurrent long-running tasks across many users — not the
DocRef shape today.
